# 전파 문안 문체 규칙(초안)과 현장 DB 연계 설계안 — 사용자 확인 대기

작성 2026-09-28. 아직 코드에 반영하지 않았다. 아래 "결정 대기" 네 가지를 사용자에게 받은 뒤 진행한다.
이 문서에는 공지 원문·실명·연락처·회의 링크·엑셀 경로·DB 내용을 넣지 않는다(공개 저장소).

## 1. 전파 문안 문체 규칙(초안)

### 1.1 받은 양식(2026-09-28, 카카오톡 단체방 공지 약 30건)

- 기상 관련: 폭염특보 다수(오전·오후·주말 전망), 호우 **단독**(예상 강수시간·지역별 강수량), 폭염+호우 복합,
  폭염+태풍 복합, 온열질환 중대재해 뒤 긴급 작업중지·작업시간 단축.
- 기상 외(틀만 참고): 교육 안내, 서류 제출, 주말·휴일작업 취합.
- 카카오톡 복사 때 붙은 "[보낸 사람] [시각]" 줄, 날짜 구분 줄, "파일: …", "메시지가 삭제되었습니다"는 양식이 아니다.
- 아직 없는 유형: 강풍 단독, 대설·한파, 특보 해제.

### 1.2 구조

1. `■ 공지드립니다.` (긴급 시 `■ 긴급 공지드립니다.`)
2. 상황 문단: 기상청 근거 + 결론. 예) "금일 기상청 기준, 전국 대부분 지역에 폭염특보가 발효 중이며, 낮 최고기온은 33~39℃까지 오를 것으로 예상됩니다."
   오후 발송은 "14시 이후 현재," "13시 현재 주요 현장권 기온이 30℃ 이상으로 확인되고 있으며," 식.
3. 당부 문단: "각 현장에서는 작업 전 체감온도 및 폭염특보 발효현황을 확인하시고, 온열질환 예방조치를 철저히 이행하여 주시기 바랍니다."
4. 【제목】: 【금일 폭염특보 및 온열질환 예방관리】, 【금일 기상예보 및 현장 수방관리】, 【금일 기상상황 및 현장 안전관리】(복합),
   【금일 오후 온열질환 예방관리】(오후), 【폭염·태풍 대비 안전관리】, 【금주 기상전망 및 풍수해 대비】(주간).
5. 번호 절 ①②③(④):
   - ① 특보 현황 / 기상상황 — **현장명이 아니라 "현장권"(서울·경기권, 강원 화천·강릉권, 경북 안동권, 부산권, 전남 곡성권)으로 묶는다.** "당사 현장 관련 특보현황/지역" 표현.
   - ② 폭염안전 5대 기본수칙 — 물 / 냉방장치 / 휴식 / 보냉장구 / 119 신고.
   - ③ 현장 조치사항.
   - (④ 이상증상 발생 시 조치)
   - 호우: ① 예상 강수시간(▶ 지역 : 시작 시각) ② 지역별 예상 강수량(▶ 지역 : 30~100mm, ※ 많은 곳 …mm 이상) ③ 현장 조치사항.
6. 마무리: "각 현장에서는 (…) 예방조치가 형식적으로 운영되지 않도록 현장 여건에 맞게 (실질적으로) 관리하여 주시기 바랍니다." → `감사합니다.`

### 1.3 표기

- 항목 `ㅇ`, 설명 줄 `  : `, 참고 `※`, 지역 목록 `▶`. 예전 공지는 `-`도 씀(최근은 `ㅇ`).
- 조치는 명사형 종결: ~확인, ~철저, ~검토, ~강화, 즉시 작업중지, 必.
- 수치: "35℃ 내외/안팎", "33℃ 이상", "30~100mm", "※ 경기북부 많은 곳 120mm 이상", "최고체감온도 38℃ 이상".
- 한 줄 약 20자 안팎(휴대폰 카톡 가독성).
- 날짜: 금일·명일·금주·차주, "8/3(월)"·"07/08(水)".
- 필요 시 "※ 위험이 판단되는 경우 '작업중지권'을 적극 행사하여 주시기 바랍니다."
- 담당자 안내가 필요하면 실명 대신 `[안전경영팀 담당 매니저]` 자리표시자.

### 1.4 현재 시스템 문안과의 차이

- 현재: 현장명 나열 + 조치 목록 + 마무리. 양식: 현장권별 현황 → 5대 수칙 → 조치사항의 3단.
- 현재: 긴 문장. 양식: 짧은 줄.
- 현장권 묶기에는 현장별 지역(시·군) 정보가 필요 → 2장의 DB 연계와 이어진다.

### 1.5 예시(시스템 자료로 생성할 경우, 수치는 예시)

```
■ 공지드립니다.

금일 기상청 기준,
당사 현장 소재 지역에 폭염특보가
발효 중입니다.

각 현장에서는 작업 전
체감온도 및 폭염특보 발효현황을
확인하시고, 온열질환 예방조치를
철저히 이행하여 주시기 바랍니다.

【금일 폭염특보 및 온열질환 예방관리】

① 당사 현장 관련 특보현황

ㅇ 경북 안동권
  : 폭염경보 / 체감온도 34.2℃(09시 관측)
ㅇ 전남 곡성권
  : 폭염주의보 / 체감온도 33.1℃(09시 관측)

② 폭염안전 5대 기본수칙

ㅇ 물
  : 시원하고 깨끗한 물 충분히 제공
ㅇ 냉방장치
  : 냉방·통풍장치 및 그늘막 설치
ㅇ 휴식
  : 체감온도에 따른 휴식시간 부여
ㅇ 보냉장구

ㅇ 119 신고
  : 이상증상 지속 시 즉시 신고

③ 현장 조치사항

ㅇ 취약근로자 건강상태 수시 확인
ㅇ 이상증상 발생 시 즉시 작업중지
```

## 2. 현장 DB 연계 설계안

### 2.1 엑셀 구조(열 이름만 확인, 2026-09-28)

- 시트 "개시사업장"(26건): 사용 열 = 공종(건축/토목), 구분(주관/비주관), 공사명, 공사장주소, 공사시작일, 공사종료일, 산재개시상태.
  **읽지 않는 열** = 안전관리자, 자격, 연락처, 이메일(개인정보), 총공사금액, 발주자명(업무 기밀), 사업개시번호(공개 금지).
- 시트 "상세주소": 지점/공사명, 우편번호, 기본주소, 상세주소(시·군까지만 사용).
- 관제 설정(`config.py` SITES, 22곳 중 1곳 꺼짐)과 공사명 정확 일치 0곳, 부분 일치 8곳, 못 찾음 14곳
  → DB는 정식 공사명, 설정은 줄인 이름이라 **처음 한 번 짝짓기 확인**이 필요하다.
- 엑셀은 업무용 PC에만 있다(경로는 저장소에 적지 않음). 집 PC에서는 이 작업을 할 수 없다.

### 2.2 도구 `scripts/sync_sites.py`(업무용 PC 로컬 전용, 아직 미작성)

1. 허용 열만 머리글 이름으로 골라 읽는다(개인정보 열은 셀을 읽지 않음). 엑셀 경로는 실행 때 입력.
2. DB 공사명 ↔ 관제 현장명 짝 후보를 로컬 화면에 보여 주고 사용자가 확인. 확인한 짝은 git 제외 폴더(`credentials/`)에 저장.
3. 현장별 공종·지역(시·군)·기상청 격자(nx, ny)·특보 구역(warning_regions/provinces)을 채우고, 종료일이 지나면 `active: false`.
   기존 현장의 공개 ID를 `id`로 고정해 이름이 바뀌어도 홈 화면 바로가기가 유지되게 한다.
4. 흩어진 설정(`SITES_JSON`, `warning_client.KNOWN_SITE_REGIONS`, `site_profile.SITE_SHORT_NAMES`)을 현장 목록 필드 한 곳으로 모은다
   (코드의 두 표는 예비값으로만 남김). 짧은 이름은 자동 추정하지 않고 사용자가 입력.
5. 추가·변경·종료 현장 표를 보여 주고 승인 시 `config.py` 갱신 + `gh secret set SITES_JSON`(내용은 출력하지 않음).
   담당자·연락처는 기존 설정 값을 보존하며 DB에서 읽지 않는다.

## 3. 결정 대기(사용자)

- (가) 새 현장 좌표: 국토부 브이월드(VWorld) 주소 검색 API(공공·무료, 키 발급 필요 — 추천) / 새 현장만 좌표 직접 입력.
- (나) 관제 대상: DB에만 있는 현장 전부 추가 / 도구가 보여 주면 선택 / "주관·비주관"으로 거르기.
- (다) 문안에서 현장명 대신 "OO권"으로 묶는 방식이 맞는지.
- (라) 양식의 "33℃ 이상 시 매 2시간 이내 20분 이상 휴식"(법정 기준 문구)을 자동 문안에 넣으려면 국가법령정보센터 원문·시행일 확인과
  `legal/` 근거 문서 갱신이 먼저 필요 — 진행 여부.
