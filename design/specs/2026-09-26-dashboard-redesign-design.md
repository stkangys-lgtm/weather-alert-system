## 1. 배경과 목표

### 1.1 현재 화면의 문제 (2026-09-25 점검)

- **A. 표현·경고색**: 확정된 사내 기준이 아닌 "선제주의/선제경계" 등급이 헤더·범례·배지·문안에 쓰이고, 21개 현장 중 12곳이 주황·빨강으로 칠해져 실제로 위험한 곳이 묻힌다. 21개 카드 모두에 같은 노란 "데이터 부족" 상자가 반복된다.
- **B. 화면 간 불일치**: 지도 화면과 카드 화면의 헤더·색·아이콘이 달라 다른 사이트처럼 보이고, 이모지·특수기호 아이콘과 영문 라벨이 섞여 있다.
- **C. 한눈에 안 보임**: 1440×900에서도 지도가 한 화면에 들어오지 않고, 지도 점에 현장명이 없으며, 지난 시각 예보가 섞여 나온다.
- **D. 모바일**: 요약 숫자와 갱신 시각이 모바일에서 사라진다.
- **E. 전파 문안**: 텍스트 파일 원본이 열려 복사해 전파하기 불편하다.

### 1.2 목표

"날씨 앱으로 판매한다면 살 만한" 품질. 참고 기준은 Flighty(실지도 위 유리 패널, 큰 숫자 하나 + 짧은 상태 글자, 부드러운 전환).

### 1.3 성공 기준

1. 1440×900 PC에서 **스크롤 없이** 전국 지도·현장 목록·선택 현장 상세·시간 스크러버가 모두 보인다.
2. 390×844 휴대폰 첫 화면에 현장명·기온·요약 문장·특보/법정 상태가 보인다.
3. 화면·문장 어디에도 "선제", "기준 도달", 확정되지 않은 등급어가 없다(자동 테스트).
4. 공개 파일(`docs/`)에 담당자 이름·연락처가 없다(자동 테스트).
5. 기상청 수집이 실패해도 마지막 정상 자료가 **시각과 함께** 보이고, "정상"으로 오인되지 않는다.
6. 지도 서비스가 멈춰도 목록·상세·요약은 그대로 동작하고 자체 지도로 전환된다.
7. 지도 준비를 기다리지 않고 목록·요약이 먼저 나타난다.

## 3. 화면 설계

### 3.1 공통 원칙

- **조건 그대로 표시**: 위험을 등급으로 부르지 않고 관측·예보 값으로 적는다("비 31mm/h", "체감 33.5°").
- **색의 예약**: 빨강·주황은 기상청 공식 특보와 법정 조치에만 쓰고, 항상 아이콘·글자와 함께 쓴다. 조건은 파란 칩 + 수치로 표시한다.
- **실측과 예보 구분**: "지금" 값은 초단기실황 관측값이며 **관측 시각(정시)**을 표시한다(예: "17:00 관측"). 나머지는 "예보"로 표시한다. 두 값이 다르면 판단 문구 없이 나란히 적는다.
- **지난 시각 제외**: 시간대별 표시는 항상 "지금"부터 시작한다.
- **설정 안내는 경고가 아니다**: 작업 정보 미등록은 회색 안내 한 줄로 표시한다.

### 3.2 본사 화면 (`/`, PC 우선)

프로토타입 `hq-prototype-v4`를 기준으로 한다.

- **배경**: 화면 전체가 실지도. 모든 패널은 지도 위에 떠 있는 반투명 유리 패널.
- **상단 막대**: 로고 · "기상안전 관제 본사" · 화면 전환(전국 관제 / 현장 목록 / 전파 문안) · 수집 상태(낮: "정상 수집 · 16:47 수집 · 다음 수집 17:47", 17:47 이후: "마지막 수집 17:47 · 다음 수집 내일 04:17").
- **왼쪽 시트**
  - 요약: 선택 시각 표시("17:00 관측" 또는 "내일 03시 예보") + 한 문장 요약.
  - 요약 숫자 4개: 기상특보 수 · 법정조치 수 · 비 오는 현장 수 · 최대 시간당 강수(현장명). 0은 흐리게.
  - 현장 목록: 정렬 전환(비 / 바람 / 기온). 행 = 왼쪽 큰 숫자 + 단위, 오른쪽 현장명·상태 한 줄·12시간 미니 막대. **특보·법정 현장은 항상 맨 위 고정.**
- **지도**: 현장 표식(점 + 이름·수치 칩, 비의 세기로 점 색), 가까운 표식 자동 묶음(확대 시 해제), 비구름 레이어, 범례("비 mm/h" + 눈금 0.1·1·3·15·30+ + 출처), 지도 조작 버튼(레이어·확대·축소·전국).
- **오른쪽 상세**(현장 선택 시 들어옴): 유형·현장명, 날씨 히어로(하늘 반응형), 특보·법정 칩, 수치 4개(비·바람·체감·습도), 앞으로 24시간 타임라인(비·바람 칸 + 기온 선, 스크러버와 연동된 세로 표시), 법정 확인 안내, 버튼(전파 문안 / 현장 화면).
- **하단 시간 스크러버**: ▶ 재생, 끌기, 키보드 ←→. 0=지금(관측), 1~24=시간별 예보. 바꾸면 지도·목록·요약 숫자·문장·상세가 모두 그 시각으로 바뀐다.
- **전파 문안 창**: 사내 문체 미리보기 + 복사 + 확인 알림.
- **좁은 화면(900px 미만)**: 지도 전체 + 아래 끌어올리는 시트(요약·목록), 현장 선택 시 상세 시트로 교체. 스크러버는 상세 시트 안 타임라인으로 대신한다.

### 3.3 현장 화면 (`/site.html?id=현장ID`, 모바일 우선)

프로토타입 `site-prototype-v2`를 기준으로 한다.

- **배경**: 현장 주변 실지도 + 비구름 레이어 + 현장 표식(맥박 효과).
- **끌어올리는 시트**(두 위치: 반쯤 / 전체), 내용 순서:
  1. 현장명 · 유형 · 지역 · "지금/지금으로" 칩
  2. 히어로: 관측 시각·날씨, 큰 기온, 체감·내일 최저/최고, 요약 문장
  3. 특보·법정 칩
  4. 수치 4개
  5. 앞으로 24시간: 좌우로 문지르면 히어로·수치가 그 시각 예보로 바뀌고 아래에 읽기 값 표시
  6. 주변 비구름: "지도로 보기"(시트를 내려 지도 펼침)
  7. 10일 예보: 단기 3일 + 중기, 기온 범위 막대, 강수확률 30% 이상만 표시, 자료 없는 날은 "예보 자료 없음"
  8. 법정 확인 안내
  9. 전파 문안: 미리보기·전체 보기·복사
  10. 출처 줄
- **PC(1024px 이상)**: 왼쪽 지도(고정), 오른쪽 내용 열(최대 560px)의 2단.

### 4.2.1 현대아산 CI 규정집(2026.4) 준수 사항

사용자가 제공한 CI 규정집과 공식 PNG를 기준으로 한다.

- **사용 파일**: 앱바에는 공식 PNG "국문 가로 시그니처 원색"(규정집 06쪽, 파일 FC-01, 567×112)을 그대로 쓰고 높이만 조절한다(PC 26px, 모바일 22px). 앱 아이콘·탭 아이콘에는 규정집 01쪽 심볼마크의 원본 벡터 좌표를 그대로 옮기고 공식 HEX(#FABE00, #009944)로 칠한 SVG를 쓴다(다시 그리지 않음). 저장소에는 필요한 파일만 영문 이름으로 `web/assets/brand/`에 넣는다.
- **배경**: 원색 시그니처는 흰 바탕이 원칙이다(13쪽). 전용색과 비슷한 색, 화려한 그라데이션, 복잡한 패턴, 사진·영상 위 사용을 금지한다(16쪽). 따라서
  - 지도 위에 떠 있는 로고 영역은 **불투명 흰 바탕**으로 한다(반투명 유리 패널 금지).
  - 하늘 반응형 히어로에 심볼 워터마크를 넣지 않는다(브레인스토밍 중 검토했던 안 폐기).
- **형태**: 비율 변경, 그림자 등 효과, 기울임·왜곡, 외곽선 표현, 규정 외 조합을 금지한다(16쪽). 파일을 가공하지 않는다.
- **보조 색상**: 규정집의 콘텐츠 색상(현대 Gold PANTONE 872 C, 현대 Silver 877 C, 현대 Black Black 6 C)에 맞춰, 흐림 글자는 현대 Silver 근사값 `#8a8d8f`, 잉크는 현대 Black 근사값 `#101820`으로 둔다(규정집에 HEX가 없어 PANTONE 근사값임). 주색 `#2b4775`는 현대 Blue에서 채도만 낮춘 화면용 색으로 유지한다.
- 규정 해석이 모호하면 CI 관리부서(현대아산 경영지원팀)와 협의한다.

### 4.3 글꼴·아이콘·형태

- 글꼴: Pretendard(OFL, jsDelivr 동적 서브셋). 수치는 고정폭 숫자(`tabular-nums`).
- 네오현대: 웹 탑재 라이선스가 불명확(눈누 요약상 서버 탑재 금지)하므로 로고 파일로만 쓴다. 웹 사용 허락을 받으면 제목 글꼴 토큰만 바꾼다.
- 아이콘: Lucide(ISC) 선 아이콘을 인라인 SVG 심볼로 한 세트만 사용. 이모지 금지.
- 모서리: 패널 22px, 카드 16~22px, 칩 999px. 그림자는 3단 은은한 그림자, 테두리 대신 층위로 구분.

### 4.4 움직임

- 등장: 패널 순차 등장, 목록 행 35ms 간격, 지도 표식 중심부터 튀어 오름.
- 전환: 스프링 곡선 `cubic-bezier(.34,1.56,.64,1)`, 일반 `cubic-bezier(.2,.8,.2,1)`.
- 숫자: 올라가며 표시(750ms). 탭이 가려져도 최종 값은 반드시 표시.
- 지도: 현장 선택 시 비행 이동.
- `prefers-reduced-motion: reduce`이면 모든 애니메이션을 끈다.

```
    ├ 문장: src/narrative.py                 (요약 문장·전파 문안)
    ├ 레이더: src/radar.py                   → docs/data/radar.png
    └ 게시: src/publish.py                   web/ → docs/ 복사
web/  (화면 원본, 사람이 수정)
  index.html, site.html, manifest.webmanifest
  assets/tokens.css, app.css, common.js, hq.js, site.js, icons.svg, icons/(앱 아이콘)
브라우저: docs/index.html · docs/site.html 이 data/latest.json 을 불러와 그린다
```

- 빌드 도구 없음(순수 HTML·CSS·JS). 계산 규칙(문장·자료 상태·정렬 기준 값)은 Python에서 만들고 JS는 표시·상호작용만 한다.
- 매 실행 커밋은 `docs/data/*`만 바뀐다. `web/`을 고쳤을 때만 화면 파일이 바뀐다.
- 기존 `docs/weather-state.json`, `latest-alert.txt`, `announcement.txt`, `notification-outbox.json`은 그대로 유지한다.
- 외부 라이브러리: MapLibre GL JS(버전 고정, 무결성 해시), Pretendard CSS(버전 고정).
- 추가 Python 패키지: Pillow, numpy(레이더 처리).

### 5.2 현장 ID·표시 이름

- `id`: 설정에 `id`가 있으면 그 값, 없으면 `site_name`의 SHA-1 앞 8자리. 이름을 바꾸면 ID가 바뀌므로 오래 쓸 현장은 설정에 `id` 지정을 권장한다.
- `short_name`(선택): 없으면 현장명 전체를 쓰고 화면에서 말줄임한다. 자동 추정은 하지 않는다(예: "오리온 진천신공장"→"오리온", 화성의 두 현장이 같은 이름이 되는 등 오류가 생김). 1단계에서 현재 21개 현장의 짧은 이름 목록을 제안해 사용자 확인을 받고 설정에 넣는다.
- `region`(선택): 없으면 `warning_provinces` 첫 항목 + `warning_regions` 첫 항목으로 조합(예: "경상북도 울진군"). 둘 다 없으면 비운다.

### 5.4 문장 규칙 (`src/narrative.py`)

- 금지어: "선제", "기준 도달", "주의 단계", "경계 단계" 등. 금지어 목록을 코드 상수로 두고 테스트로 검사한다.
- 세기 표현은 기상청 공식 분류만 쓴다(출처: 기상청 예보용어, 2025-06-11, 예보업무규정 제5조 세부지침). 비: 빗방울(0.1mm 미만)·약한 비(3mm/h 미만)·비(3~15, 원문 "(보통) 비")·강한 비(15~30)·매우 강한 비(30 이상). 바람: 약한 바람(4m/s 미만)·약간 강한 바람(4~9)·강한 바람(9~14)·매우 강한 바람(14 이상, 강풍주의보 수준). 원문 규칙에 따라 바람은 수치를 기본으로 쓰고 4m/s 이상에서만 표현을 붙이며, 비는 모든 단계에 표현을 붙인다.
- 실측·예보 병기: 지금 비가 오면 "지금 시간당 {관측}mm(관측)의 {세기 표현}. 예보는 {다음 비 시간대} {예보 표현}."을 쓴다. "훨씬", "크게" 같은 판단어는 쓰지 않는다.
- 비가 없으면 "지금은 비가 없습니다. 예보상 {시각}부터 비(강수확률 {pop}%)." 또는 "24시간 안에 비 예보가 없습니다."
- 전파 문안은 사내 문체를 따른다(■ 공지드립니다 → 상황 → 【제목】 → ㅇ 조치 → 이행 촉구 → 감사합니다). 조치 문구는 `alert_rules.ACTION_ITEMS`를 재사용한다. 실명·연락처는 넣지 않는다.
- 스크러버로 고른 예보 시각의 짧은 문장("내일 3시 예보상 4곳에 비")은 JS가 고정 틀로 만든다.

### 5.5 마지막 정상 자료 유지

- 수집 전에 직전 `latest.json`을 읽는다. 이번에 현장의 실황을 받지 못하면 직전 현장 항목을 복사하고 `state: "stale"`, `as_of`는 직전 관측 시각으로 둔다.
- 직전 자료도 없으면 `state: "missing"`, 수치는 비운다.
- 화면: stale이면 값을 흐리게 하고 "15:00 관측 자료 · 이번 수집 실패"를 표시한다. missing이면 "자료 없음"을 표시하고 정렬에서 맨 아래.
- 특보 조회 실패는 `status.warnings: "failed"`로 표시하고 화면에 "특보 확인 실패" 칩을 띄운다("특보 없음"으로 보이지 않게).

### 5.6 수집 일정 표시

- 다음 수집 시각은 워크플로 일정으로 계산한다. :47이 주 실행이고 :17 보완 실행은 직전 수집이 45분 넘게 지났을 때만 수집하므로, 낮에는 "다음 정시 :47"을 표시한다. 17:47 이후에는 다음 날 첫 실행인 04:17(전날 자료가 오래되어 실제 수집함)을 표시한다.
- 운영시간 밖에는 "마지막 수집 17:47 · 다음 수집 내일 04:17"을 상단에 표시한다.

### 5.7 지도

- MapLibre + OpenFreeMap `positron` 스타일. 도시·도·바다 이름만 한국어(`name:ko` 우선)로 남기고 나머지 라벨은 숨긴다. OpenStreetMap 출처 표기 유지.
- 표식 묶음: 화면 좌표 기준 44px 안의 표식을 우선순위(특보·법정 → 비 많은 순)로 묶는다. 이동·확대가 끝날 때 다시 계산한다. 묶음 칩은 "개수 · 이름 · 비 최대 N"을 보여주고, 누르면 구성 현장이 모두 보이게 확대한다.
- 대체 지도: 지도 스타일이 **화면이 보이는 동안 누적 9초** 안에 준비되지 않거나 라이브러리를 못 불러오면 기존 `kr_map_data.json`으로 만든 SVG 지도로 전환한다. 뒤쪽 탭에서는 브라우저가 그리기를 늦추므로 숨은 시간은 세지 않는다(프로토타입에서 오판정 확인). 전환 뒤 실지도가 늦게 준비되면 안내를 지우고 실지도로 돌아간다. SVG 원본은 `docs/data/kr-map.json`으로 게시한다.

### 5.8 레이더 (`src/radar.py`)

1. `RadarImgInfoService/getCmpImg`(`data=CMP_WRC`, 오늘 날짜)에서 가장 최근 파일을 고른다. 기존 `KMA_API_KEY`를 사용한다(활용신청 완료, 동작 확인).
2. 이미지(635×620 PNG, 배경·경계선·제목·범례 포함)를 내려받는다.
3. 범례 막대에서 "색 → mm/h" 표를 자동으로 읽고, 표에 있는 색 점만 남긴다(나머지는 투명).
4. 영상의 투영을 기준점(해안선·섬·위경도 격자)으로 보정해 픽셀 → 위경도 변환을 구한다. `grid_converter.py`의 기상청 LCC 공식을 우선 가정한다.
5. 웹 지도 좌표로 재투영하고, 우리 비 단계 색으로 다시 칠해 `docs/data/radar.png`로 저장한다. 네 모서리 위경도와 영상 시각을 `latest.json`에 적는다.
6. 출처 "자료: 기상청"(공공누리 1유형)과 영상 시각을 화면에 표시한다.

- **수용 기준**: 기준점 오차가 지도상 5km 이내. 넘으면 지도 겹치기를 끄고 현장 화면에 "레이더 원본 영상 보기" 카드(기상청 원본 이미지)로 대체한다.
- 영상이 90분보다 오래되면 레이어를 숨기고 "레이더 자료 없음"을 표시한다.
- 파일은 한 장만 덮어쓴다(예상 연간 수백 MB 이내 증가). 저장소가 1GB에 가까워지면 커밋 없는 Pages 배포로 전환을 검토한다.

### 5.9 홈 화면 추가

- `manifest.webmanifest`(이름 "현대아산 기상안전", 시작 주소, 테마색 `#2b4775`). 아이콘은 4.2.1의 심볼 SVG를 흰 바탕 정사각형에 여백을 두고 192·512px로 만든다(원색 심볼 + 흰 바탕은 규정집 원칙). 탭 아이콘은 같은 SVG를 쓴다. 현장 화면에서 추가하면 그 현장 주소로 시작한다.
- 서비스 워커(오프라인 캐시)는 1차에 넣지 않는다.

### 5.10 캐시

- `latest.json`은 `fetch(..., {cache: "no-cache"})`로 받는다. GitHub Pages CDN이 최대 10분 캐시할 수 있으므로, 화면의 "수집 시각" 표시를 기준으로 판단하도록 한다.

## 7. 보안·개인정보·접근성

- 공개 파일 허용 목록 방식으로 데이터 구성. 테스트는 가짜 담당자 이름·전화번호를 넣은 테스트용 현장으로 `latest.json`과 게시 결과를 만들어, 그 값과 전화번호 형식이 어디에도 없는지 검사한다(실제 설정에 의존하지 않음).
- 외부 스크립트는 버전 고정 + 무결성 해시(SRI) + `crossorigin`.
- 색만으로 의미를 전달하지 않는다(아이콘·글자 병기). 글자 대비 4.5 이상. 키보드로 현장 선택·스크러버 조작 가능. 지도 표식에 접근성 이름 제공.
- 지원 브라우저: 최근 2년 이내 Chrome·Safari·Edge·삼성 인터넷.

## 9. 배포 단계

각 단계는 테스트 통과 + 화면 확인 + 사용자 확인 후 다음 단계로 간다.

1. **데이터 층**: `view_model.py`, `narrative.py`, 마지막 정상 자료 유지, `latest.json` 생성. 기존 화면은 그대로.
   - 완료 기준: Actions 실행 후 `docs/data/latest.json`이 스키마를 만족하고 개인정보·금지어가 없음.
2. **공통 디자인 + 본사 화면**: `web/` 신설, `publish.py`, 새 `index.html`. 기존 화면 생성은 2주간 `docs/old/`로 계속 만든다.
   - 완료 기준: 1440×900 스크롤 없음, 스크러버·정렬·선택·전파 문안 동작, 지도 장애 시 SVG 전환.
3. **현장 화면 + 홈 화면 추가**: `site.html`, 매니페스트, 아이콘.
   - 완료 기준: 390×844 첫 화면 기준 충족, 시트·타임라인 문지르기·복사 동작.
4. **레이더**: 먼저 좌표 보정 시험(수용 기준 5km) → 통과 시 레이어 적용, 실패 시 원본 영상 카드.
5. **정리**: `dashboard.py`·`map_dashboard.py`와 해당 테스트 삭제, `docs/old/` 제거, `sites.html`·`map.html`은 새 화면으로 이동하는 안내 페이지, README·CLAUDE.md 갱신.

## 10. 준비물과 열린 항목

- **현대아산 공식 로고 파일(확보, 2026-09-26)**: 사용자가 CI 규정집(2026.4)과 공식 PNG(원색·Positive·Negative 각 변형)를 제공했다. 구현 시 필요한 파일만 `web/assets/brand/`로 복사한다.
- 현장별 `short_name`·`region`·`id`(선택): 없으면 5.2의 대체 규칙. 짧은 이름은 1단계에서 목록을 제안해 확인받는다.
- 기상청 강수 강도·풍속 표현의 경계값: 원문 확인 완료(5.4).
- 네오현대 웹 사용 문의(선택): hdpr@hyundaigroup.com.
- 중기예보 날짜 밀림(원인 확인, 2026-09-26): 18시 발표에는 "4일 뒤" 값이 비고 5일 뒤부터 오는데, 기존 `combine_forecast`는 날짜를 실행한 날(오늘) 기준으로 계산한다. 그래서 전날 18시 발표를 쓰는 새벽 실행(04:17~06:17)에는 중기예보 날짜가 하루씩 밀린다. 1단계에서 발표일 기준으로 고친다.
- 야간 수집: 공개 저장소는 Actions 사용 시간이 무료이므로 비용 제약은 없다. 운영 여부는 별도로 정한다.
